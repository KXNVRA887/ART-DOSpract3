# Практическая работа № 3
## Разработка матрицы тест-кейсов и критериев приёмки

**Дисциплина:** Программирование и прототипирование ИТ-решений  
**Вариант:** Б, приём пакета измерений

## 1. Участники, роли и параметры

| Участник | Номер | Роль в первой части | Роль после обмена |
|---|---|---|---|
| Доскарин Дамир Талгатович | N₁ = 10 | аналитик | разработчик |
| Артыков Азизбек Сайфидинович | N₂ = 2 | разработчик | аналитик |

N = N₁ + N₂ = 10 + 2 = **12**.
K = 8 + N % 5 = 8 + 2 = **10** отсчётов.
Стресс-пакет: 1000 × K = **10 000** отсчётов.

## 2. Цель и объект проверки

Цель: доказать с помощью тест-кейсов, что функция приёма пакета отсчётов давления (МПа) выполняет контракт. Проверяется только функция `check(values, capacity)` из `service.py`, без сети и оборудования. Пакет принимается или отклоняется целиком.

## 3. Критерии приёмки (в порядке приоритета)

| ID | Критерий |
|---|---|
| Б1 | Не список → TYPE. Пустой список → EMPTY. |
| Б2 | Длина больше K → OVERLOAD до проверки элементов. |
| Б3 | В непустом пакете длиной не более K есть нечисловое значение (включая bool) или давление вне [0; 60] → BAD_ITEM. |
| Б4 | Все элементы допустимы, длина от 1 до K включительно → OK. |
| Б5 | Пакет длиной 1000 × K → OVERLOAD без исключения. Следующий допустимый пакет → OK. Частичный приём недопустим. |

## 4. Классы эквивалентности и границы

| Признак | Допустимые | Недопустимые | Проверенные границы |
|---|---|---|---|
| Тип пакета | list | другой тип (None) | — |
| Длина | 1…10 | 0; больше 10 | 0, 10, 11; перегрузка 10 000 |
| Тип отсчёта | int, float | прочие, в том числе bool | — |
| Давление, МПа | 0…60 | меньше 0; больше 60 | −1, 0, 60, 61 |

## 5. Условия испытаний

- Python 3.13.18, ОС Linux; внешние библиотеки не используются.
- N = 12, K = 10, функция `check(values, capacity)`.
- Предусловие: `check` импортирован из `service.py`, K вычислено.
- Обычный тест (Б-01…Б-08): один раз вызвать `check(вход, K)` и записать ответ.
- Б-09: вызвать `check([30] * 10000, K)`, затем `check([30], K)`.
- Б-10: вызвать `check([30] * 10000, K)`, затем `check([30] * 10, K)`.
- Ожидания взяты из контракта (оракул), а не получены вызовом проверяемой функции.
- Исключение перехватывается отдельно для каждого тест-кейса, записывается с именем класса и даёт FAIL; остальные сценарии выполняются.

## 8. Проверка чувствительности (намеренный дефект)

Изменение во временной копии `service.py`: `len(values) > capacity` заменено на `len(values) >= capacity`. Исходный файл сохранён без изменений.

**Прогноз по коду:** пакет длиной ровно K будет ошибочно отклонён. Должны упасть Б-02 и второй вызов в Б-10. В остальных пакетах, которые должны приниматься или доходить до проверки элементов, длина меньше K, а пакеты Б-08 и первые вызовы Б-09, Б-10 длиннее K.

## 9. Восстановление и повторный прогон

После перегрузки из 10 000 отсчётов отправляется ровно K = 10 допустимых (тест **Б-10**, ожидание `('OVERLOAD', 'OK')`). На исходной версии получен ожидаемый результат. В версии с дефектом получено `('OVERLOAD', 'OVERLOAD')`. При этом Б-09 остался зелёным: пакет из одного отсчёта не достигает границы.

### Повторный прогон после возврата к исходной версии (protocol_retest.txt)

```text
# Python 3.13.18; N=12; K=10
Б-01 | OK | OK | PASS
Б-02 | OK | OK | PASS
Б-03 | TYPE | TYPE | PASS
Б-04 | EMPTY | EMPTY | PASS
Б-05 | BAD_ITEM | BAD_ITEM | PASS
Б-06 | BAD_ITEM | BAD_ITEM | PASS
Б-07 | BAD_ITEM | BAD_ITEM | PASS
Б-08 | OVERLOAD | OVERLOAD | PASS
Б-09 | ('OVERLOAD', 'OK') | ('OVERLOAD', 'OK') | PASS
Б-10 | ('OVERLOAD', 'OK') | ('OVERLOAD', 'OK') | PASS
# ИТОГО: запланировано=10; PASS=10; FAIL=0; не выполнено=0
```

**О длительности.** Время не измерялось, требования к быстродействию в контракте нет. Даже измеренная длительность одного прогона не доказывает быстродействие на любом компьютере: она зависит от процессора, версии Python, ОС и фоновой нагрузки, а один замер не показывает разброс. Кроме того, при перегрузке функция проверяет длину и не перебирает элементы; список создаётся ещё до вызова. Поэтому тест подтверждает предсказуемый отказ и приём следующего пакета, но не производительность системы под длительной нагрузкой.

## 10. Решение о приёмке

**Исходная версия `service.py` принята.** Выполнено 10 из 10 проверок: PASS 10, FAIL 0, невыполненных нет. Каждый критерий Б1–Б5 покрыт выполненным тестом, повторный прогон тоже дал 10 PASS, открытых расхождений в этой версии нет.

**Версия с дефектом D-01 не принята:** Б-02 и Б-10 дали FAIL.

Вывод относится к проверенным входам и контракту учебного сервиса.

## 11. Ответы на контрольные вопросы

**1. Почему отказ для ошибочного ввода может быть PASS?**
Статус показывает совпадение факта с ожиданием, а не факт приёма данных. В Б-06 вход `[61]` выше предела 60 МПа, ожидается BAD_ITEM. Функция вернула BAD_ITEM, поэтому статус PASS.

**2. Какая ошибка останется незамеченной, если тестировать только середину интервала?**
Ошибки на границах. Например, замена `0 <= x <= 60` на `0 < x < 60` отклонит допустимые 0 и 60, но тест со значением 30 останется зелёным. То же с длиной: короткий пакет не выявляет замену `>` на `>=`.

**3. Чем стресс-сценарий отличается от обычной проверки за границей и что показывает вызов после перегрузки?**
Проверка за границей берёт ближайшее значение по другую сторону порога (11 элементов). Стресс-сценарий даёт объём намного выше обычного (10 000 элементов). Вызов после перегрузки показывает, что сервис по-прежнему принимает допустимый пакет и отказ не оставил его в нерабочем состоянии.

**4. Какие тесты заметили намеренный дефект и почему остальные остались зелёными?**
Б-02 и Б-10, потому что только в них допустимый пакет имеет длину ровно K = 10. В Б-01 и Б-09 принимаемые пакеты короче K. В Б-03 и Б-04 функция завершается раньше сравнения с K. В Б-05…Б-07 длина меньше K. В Б-08 длина 11 даёт OVERLOAD при обоих условиях.

## 12. Запуск проекта

### Автозапуск в VS Code

1. Установить Python 3.11+ и VS Code.
2. Распаковать архив и открыть папку `prac3` (**File → Open Folder**). В Windows можно запустить `start.bat`, если доступна команда `code`.
3. Подтвердить доверие к папке (**Trust**).
4. Разрешить автоматические задачи: `Ctrl+Shift+P` → **Tasks: Manage Automatic Tasks** → **Allow Automatic Tasks**.
5. Выполнить `Ctrl+Shift+P` → **Developer: Reload Window**. После этого тесты запускаются при открытии папки.

Автозапуск настроен в `.vscode/tasks.json` (`"runOn": "folderOpen"`). Это запуск при открытии папки в VS Code, а не при включении компьютера. Ручной запуск: **Tasks: Run Test Task**.

Задача вызывает `python` в Windows и `python3` в macOS/Linux. Если в Windows работает только `py`, замените `"python"` на `"py"` в `tasks.json`.

### Запуск из терминала

```text
python run_all.py                 # три прогона, обновляет три протокола
python check.py > protocol.txt    # только проверка текущей версии
```

Протоколы в этом отчёте получены на Python 3.13.18. Повторный запуск перезаписывает файлы протоколов; если версия Python на вашем компьютере другая, укажите её в разделах 5, 7–9.
